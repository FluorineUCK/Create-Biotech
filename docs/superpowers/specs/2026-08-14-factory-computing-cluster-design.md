# 工厂计算集群与实时样板供应设计

## 1. 目标与范围

本功能为 Create Biotech 增加一套以生物计算为主题的工厂订单系统。它借鉴 AE 合成终端的检索和任务展示方式，但不复制 AE 的预规划合成 CPU：任务下单后实时展开，依靠装有村民的计算机多方块逐级派发，并通过 Create 现有物流网络、仓储管理器、打包机和工厂仪表执行实际物流与加工。

本阶段注册四个方块：

1. **工厂面板**（Factory Panel）：仓储检索、下单、任务与集群监视终端。
2. **样板存储核心**（Pattern Storage Core）：由讲台与装有图书管理员的纸箱转化而来，是书库多方块唯一核心。
3. **计算机**（Computer）：装入村民后成为一个独立、愚钝且不可抢占的计算节点。
4. **计算机外壳**（Computer Casing）：计算机多方块的专用封闭外壳和内部物理总线，使用现有 `biotech_casing` 材质但拥有独立方块 ID。

本功能不创建私有物品库存、不复制 Create 物流目录、不强制加载区块，也不建立全局任务目录。实际库存始终由 Create 仓储管理器读取；已经发出的包裹仍由 Create 原生物流处理。

## 2. 核心身份

系统使用两类互相独立的身份：

- `clusterId`：随机 UUID，隔离同一世界中的计算集群、样板供应与面板。
- `logisticsId`：Create `LogisticallyLinkedBehaviour.freqId`，标识可读取和请求的仓储物流网络。

一个集群保存一个**有序且去重的** `LogisticsBinding` 集合。每项至少包含：

```text
logisticsId: UUID
alias: Component/String
```

面板、计算机结构和样板供应结构必须具有相同 `clusterId`，并同步同一组允许访问的 `logisticsId`。任何订单都必须显式选择其中一个 `logisticsId`；单个订单不会跨网络取料或合并完成判定。

### 2.1 多物流网络面板

- 面板可以绑定、移除和重命名多个物流网络。
- 绑定操作复用 Create `LogisticallyLinkedBlockItem` 的交互语义和权限检查，但不能在同一 BE 中挂载多个 `LogisticallyLinkedBehaviour`：Create 以 `BehaviourType` 为键保存行为，同类型行为会相互覆盖。
- 因此面板自行保存 `LogisticsBinding` 列表，并按每个 UUID 调用 Create 的物流查询接口。
- 仓储页面支持单网络视图和“全部网络”汇总视图。
- “全部网络”仅用于搜索和比较；下单前必须选择一个具体网络。
- 最终配送目标为 `(logisticsId, deliveryAddress)`，避免不同网络中的同名地址产生歧义。
- 服务器在绑定、打开面板和下单时分别调用 Create 的 `mayInteract`/`mayAdministrate` 权限判断，不能信任客户端提交的 UUID。

### 2.2 集群绑定流程

1. 未放置的面板方块物品右击 Stock Ticker 或其他合法 Create 物流节点，将对应 `freqId` 追加到绑定列表；重复 UUID 不增加。
2. 放置第一个新面板时生成 `clusterId`。
3. 潜行使用扳手点击面板进入短期“集群绑定模式”。
4. 再点击已形成的计算机外壳或样板存储核心，将面板的 `clusterId` 与完整物流绑定集合写入目标结构。
5. 计算机协调节点把绑定传播给当前结构中的所有计算机。
6. 新面板可从已有面板复制 `clusterId` 和物流绑定集合，因此一个集群允许多个无任务状态的访问面板。
7. 仅当所有根任务已停止、没有活动 epoch 且本地邮箱为空时允许改绑。

面板“无状态”是指它不持有任务、样板、计算帧或加工状态；身份绑定和 UI 偏好属于面板配置，不属于运行状态。

### 2.3 已加载成员发现

多个物流 UUID 不能通过给一个 BE 重复添加 `LogisticallyLinkedBehaviour` 实现。集群通信因此使用一个仿照 Create `LogisticallyLinkedBehaviour.LINKS` 的**纯运行时已加载成员索引**：

- 以 `clusterId` 和稳定成员 UUID 为键，只保存当前已加载 BE 的弱引用、成员类型、当前空间地址及物流绑定集合摘要。
- 面板、样板核心和计算机协调节点在 `onLoad` 注册，在区块卸载、移除或换 Level 时注销。
- Sable 移动后由正常卸载/加载重新发布当前位置和 sublevel 身份，不需要持久化坐标目录或 Sable Mixin。
- 索引不保存任务、epoch、样板、offer、reply、历史状态或离线成员，因此不是全局任务目录，也不使用 `SavedData`。
- 离线 epoch 成员仍由各计算机本地持久化的冻结成员快照识别；运行时索引为空不能证明成员已被删除。
- 每次解析目标都再次核对 `clusterId`、根维度和订单 `logisticsId`，不能只相信缓存地址。

一个 `clusterId` 同时只允许一个活动计算机多方块和一个活动样板供应多方块；面板数量不限。两个计算机结构或两个样板核心被绑定到同一集群时，运行时索引报告身份冲突，双方拒绝接受新任务，直到玩家停止任务并解除其中一个绑定。

## 3. 样板供应多方块

### 3.1 核心形成与图书管理员生命周期

样板存储核心通过 Create 风格的物品应用形成：

```text
讲台 + 装有成年图书管理员村民的纸箱 -> 样板存储核心 + 空纸箱
```

转换是服务端原子操作：先验证上方空间、纸箱内容、图书管理员职业和实体数据可解码，再替换讲台并消费纸箱内容。失败时讲台、纸箱和村民均不改变。

核心为同一方块的上下两部分：

- 下半部分是唯一 BE 和逻辑核心，保存全部结构、图书管理员和查询状态。
- 上半部分无独立 BE，只保留图书管理员渲染空间。
- 上半部分不计入书库成员数量或跨度，也不参与书架连接。
- 书架只能从下半核心的四个水平方向或下方接入，不能从核心上方桥接。
- Create/Sable 移动必须同时收集上下两部分。

核心保存图书管理员的完整、可逆实体快照，包括 UUID、职业等级、生命、名称、交易、原始 AI/静默/交互状态及其他数据组件。工作期间不在服务端保留第二个活动村民实体；客户端参照唤魔者附魔室渲染一个只用于表现的图书管理员模型。

图书管理员与计算机中的村民不同：它可以被正常释放。

- 普通拆除：释放原图书管理员并掉落讲台。
- 潜行扳手拆解：原地还原讲台并释放原图书管理员，不掉落样板核心物品。
- 释放时恢复原 AI、交易、交互和其他实体状态。
- 若没有安全释放位置，可控拆解操作被拒绝，核心保留村民快照并进入待释放提示状态。
- 源核心只有在成功生成且确认同一村民实体后才删除快照。
- 样板核心本身不作为可反复搬运的普通掉落物获取。

村民快照**不得**通过 `Clearable.clearContent()` 清空。原版 `/setblock`、`/fill`、`/clone` 也会调用 `Clearable.tryClear()`，将实体快照当库存会造成永久丢失。Sable 搬运依赖 `isMoving=true` 抑制源端释放，目标端从移动前保存的完整 NBT 恢复快照；正常 `isMoving=false` 移除才执行释放。

### 3.2 书库结构

从核心下半部分进行六方向 flood-fill，但核心的上方向被保留的上半方块封闭。合法成员只有：

- 一个样板存储核心（上下两部分合计一个逻辑成员）；
- 原版普通书架；
- 原版雕纹书架。

规则如下：

- 每个联通分量必须恰好有一个核心。
- 两个核心通过书架连通时，整个分量进入核心冲突状态，不由坐标顺序抢占。
- 默认最多 `64` 个逻辑成员。
- 任一坐标轴上的成员跨度默认最多 `16` 格。
- 扫描发现第 65 个成员或越过跨度时立即停止并报告结构过大。
- 书库断开后，有核心的一侧重新形成结构；无核心的一侧只是普通书架。
- 已形成结构的任何已知成员区块卸载时保留上次结构快照并暂停，不读取或加载缺失区块，也不把卸载误判为断裂。
- 尚未形成的新结构只有在整个候选联通分量已加载时才能形成。

### 3.3 容量、队列与搜索预算

样板内容直接保存在雕纹书架里的书与笔页面中：

- 每本书与笔提供 `100` 个页码槽位。
- 一个装满六本书与笔的雕纹书架最多提供 `600` 个样板页。
- 空白页不产生样板，但保留其页码身份。
- 雕纹书架中的效率附魔书不提供样板页；它提高搜索预算。

派发并行度：

```text
patternQueueCount = 1 + 普通书架数量
```

没有普通书架时，每 tick 最多从基础队列发出一个已找到的样板。普通书架增加独立轮询队列，但不增加每 tick 的页面搜索预算。

图书管理员等级决定基础页面检查预算：

| 等级 | 基础页数/tick |
|---|---:|
| 新手 | 8 |
| 学徒 | 16 |
| 熟练工 | 32 |
| 专家 | 64 |
| 大师 | 128 |

效率书增益采用：

```text
efficiencyBonus(level) = level² + 1
searchBudget = min(600, librarianBase + Σ efficiencyBonus)
```

搜索实现为增量游标加工作预算：

- 每检查一个页面记录消耗一个预算单位。
- 多个查询队列轮询共享预算，单个大查询不能长期独占。
- JSON 只在书、页面、雕纹书架槽位或结构成员变化后重新解析。
- 缓存按“雕纹书架位置 + 槽位 + 页码 + 内容指纹”局部失效，不因一页变化重扫整座书库。
- 结构首次形成时也按预算分批建立索引，禁止同步解析全部页面。
- 任务选择样板后复制不可变 `PatternRecord` 快照；后续书页编辑只影响未来查询。

### 3.4 样板 JSON

一个非空页面保存一个加工样板，版本 1 的基本形式为：

```json
{
  "v": 1,
  "in": [
    {"item": "minecraft:iron_nugget", "count": 9}
  ],
  "out": [
    {"item": "minecraft:iron_ingot", "count": 1}
  ],
  "to": "iron_processing"
}
```

规则：

- `v` 是必需格式版本。
- `in` 允许多个输入；输入可指定 `item` 或 `tag`，并可带精确 Data Components 条件。
- `out` 允许多个明确物品输出；`out[0]` 是主产物，其余是副产物。
- `count` 必须为正数并通过溢出检查。
- `to` 是加工步骤的 Create 包裹地址 `recipeAddress`，不是订单最终地址。
- `to` 在订单选定的 `logisticsId` 内解析；同一个页面可以在多个允许网络中复用。
- 缺少主产物、地址、版本，互斥字段并存，数量非法或 JSON 无法解析时，只禁用该页。
- 错误记录保留书架位置、槽位、页码和简短原因，供面板定位；其他页面继续工作。

## 4. 计算机多方块

### 4.1 外壳与总线

计算机结构是轴对齐、完整封闭的长方体，扫描方式参考爆破室：由候选计算机枚举可能边界，验证整个体积，而不是依赖无限全局目录。

默认限制：

- 每轴最小 `3`、最大 `7`。
- 最大扫描体积 `7 × 7 × 7 = 343`。
- 结构内最多 `32` 个计算机方块。
- 允许 `3×5×7` 等非立方长方体。

外层每个位置都必须是专用计算机外壳，不能由计算机替代。内部允许：

- 空气；
- 计算机；
- 作为内部总线的计算机外壳；
- 后续通过专用内部组件 tag 明确加入的扩展组件。

每台计算机必须直接接触计算机外壳，或通过六方向连续的内部外壳总线连接到外层外壳。悬空、隔离或越界的计算机使结构无效。外壳孔洞、非法内部方块、超过尺寸/节点上限、跨空间组成均不能形成结构。

结构覆盖的任一区块卸载时，整个计算结构暂停并保留上次边界与成员快照；它不强制加载区块，也不在部分可见时重新判定破损。

### 4.2 无独立核心的协调节点

计算机结构不增加第五个核心方块。每个计算机创建稳定 `computerId`，首次形成时按 UUID 稳定排序，最小者成为协调节点。选择不依赖 `BlockPos`，所以 Sable 平移或旋转不会换主。

协调节点只负责：

- 验证外壳、内部总线和成员身份；
- 保存结构边界及 epoch 成员摘要；
- 接受面板绑定；
- 聚合面板需要的集群状态。

它不集中调度任务。每个计算机仍独立持有控制队列、工作槽、offer、reply 和 dispatch。

结构摘要在成员间冗余保存。当前 epoch 内协调节点被破坏时，结构进入 `SLP(OFFLINE)`，不自动换主；玩家停止所有任务并重新组网后才能选择新协调节点。没有活动任务时可立即重新选举。

### 4.3 生物装入与固定硬件配置

空计算机通过使用装有合法实体的纸箱装入生物并返还空纸箱。装入是原子操作，生物参数在此刻固定，直到计算机方块被破坏；工作期间不能通过扳手或纸箱取出、升级、治疗或改换职业。

支持成年普通村民、流浪商人和僵尸村民。计算机保存完整实体快照，但调度只读取锁定后的硬件配置。

普通村民配置：

| 等级 | 其他村民 slots/depth | 图书管理员 slots/depth |
|---|---:|---:|
| 新手 | 1/1 | 4/2 |
| 学徒 | 2/1 | 6/2 |
| 熟练工 | 3/2 | 8/3 |
| 专家 | 4/2 | 12/3 |
| 大师 | 4/2 | 16/4 |

特殊配置：

| 生物 | slots/depth | 附加能力 |
|---|---:|---|
| 傻子村民 | 1/0 | 在确定性任务环中执行根级 `LOOP_ABORT` |
| 流浪商人 | 2/1 | 每个当前 epoch 成员使样板通信距离增加 64 格 |
| 僵尸村民 | 0/0 | 不接受任务，仅作为无效硬件存在 |

破坏计算机方块时：

- 掉落空计算机方块；
- 释放原生物并恢复 AI、交互和实体数据；
- 将生命设置为半颗心；
- 流浪商人的原有消失计时从保存值继续，不在计算机内部倒计时。

Sable 移动与图书管理员核心相同：`isMoving=true` 时不释放，目标端从移动前 NBT 恢复。实体快照不属于 `Clearable` 内容。

## 5. 通信距离与空间规则

距离限制只适用于**计算机结构到样板供应核心**的查询通信：

```text
patternRange = min(512, 64 + 64 × 当前 epoch 中的流浪商人节点数)
```

- 距离取计算机结构边界中心到样板核心下半部分中心。
- 世界与 sublevel 坐标先通过 `SubLevelCompat` 转成外部坐标，再计算欧氏距离。
- 流浪商人必须属于已冻结 epoch；运行中新增不会立即扩大距离。
- 超距时相关帧进入 `SLP(PATTERN)`，重新进入范围后恢复。
- 计算机结构内部通信、面板访问和 Create 物流查询不受此物理距离限制。

单个样板供应或计算机多方块必须完整位于同一个空间，不能跨世界/sublevel 边界组成。但同一集群的面板、计算机结构和样板供应可以分别位于主世界或不同 sublevel，条件是：

- 根维度相同；
- `clusterId` 相同；
- 订单选择的 `logisticsId` 位于双方允许集合中。

跨根维度绑定直接拒绝。所有空间身份、外部坐标、方向和交互范围判断尽量复用 `SubLevelCompat`，不复制 Sable 转换算法，也不新增仅为本功能服务的 Sable Mixin。

## 6. 工厂资源模型

### 6.1 仓储库存

仓储数量只来自订单所选 `logisticsId` 的 Create `LogisticsManager`/Stock Ticker 实际容器汇总：

- 不把 Request Promise 当作库存；
- 不把运输中的包裹当作库存；
- 不维护 AE 风格的 CPU 私有物品库存；
- 多个任务共享并竞争真实仓储内容。

任务在每次需要材料、验证子任务结果、加工派发和最终配送前重新读取实际库存。如果所需物品被其他任务先取走，当前帧回到依赖循环，而不是凭旧快照继续执行。

### 6.2 加工代理

现有 Create Factory Gauge 是物理 `ProcessingProxyNode`。系统忽略其旧式上游仪表连接，只读取：

- 输入与输出；
- 所属 `logisticsId`；
- 加工地址；
- 当前是否已加载、可用。

任务搜索依赖时，把物理工厂仪表与样板书库中的虚拟 `PatternRecord` 作为同一类候选加工代理。候选必须属于当前订单网络；虚拟样板的 `to` 地址也在该网络中解析。

### 6.3 最终配送

根订单必须提供非空、格式合法的 `deliveryAddress`，并与选定 `logisticsId` 组成最终目标。加工步骤的 `recipeAddress` 与最终配送地址互不替代。

最终流程：

1. 最终产物进入仓储管理器可见的真实容器。
2. 根帧重新读取仓储并确认实际数量。
3. 根帧从选定物流网络请求实际产物，由 Create 打包发送至 `deliveryAddress`。
4. 派发成功后，有限订单完成；连续订单释放当前计算资源并从最弱节点重新排队下一批。

暂时无路由或打包机繁忙进入 `SLP(ROUTE)`，不会自动重发已经确认发出的包裹。

## 7. 实时任务与 MCU 调度

### 7.1 基本语义

任务不先构造完整 DAG。下单后立刻创建根帧，实时读取仓储、选择加工方式、展开直接依赖并派发子帧。

计算机模拟单片机：进入 `SLP` 的计算机仍被当前帧占用，不能执行另一项操作。所有计算在 Minecraft 服务端 tick 中推进，不创建操作系统线程。

任务帧状态仅有：

- `RUN`
- `WAIT`
- `SLP`
- `BLOCK`
- `HALT`

原因作为独立字段，例如：

- `WAIT(NODE)`，UI 显示 `too_many_threads`；
- `SLP(CHILD|STOCK|MATERIAL|PATTERN|PROXY|STORAGE|OFFLINE|LOOP|ROUTE)`；
- `BLOCK(WIDTH|DEPTH)`；
- `HALT(OK|CANCEL|FAULT|LOOP_ABORT)`。

计算机本身只显示 `IDLE`、`RUN` 或 `SLP`。

### 7.2 节点本地状态

每台计算机只管理自身：

- 控制队列；
- 直接子任务工作槽；
- 进入的任务 offer；
- 发出的 reply；
- 当前加工 dispatch。

`slotCount` 表示该帧可同时维持的直接子工作槽，不包含父帧自身。父帧等待孩子时留在控制队列并占用本机。

### 7.3 低到高派发

每个根任务和每个新子任务都从当前 epoch 中最弱的可用层级开始：

1. 弱节点探测真实库存并合并直接依赖。
2. 根据实际缺口计算 `requiredThreads` 与 `requiredDepth`。
3. 能力不足时把同一帧尾递交给下一档节点。
4. 目标 ACK 后，源节点立即删除 offer 并释放，不保留调用栈。
5. 最低且足够的节点正式接受帧。

`requiredThreads` 统计合并后的不同加工分支，不统计配方格数或物品数量。合并键至少包含精确输出栈与组件、选定样板/代理、加工地址及严格端点身份。

如果当前 epoch 中存在能力足够但忙碌的最低档节点，帧进入 `WAIT(NODE)`，不会为普通工作抢占更强节点。高端节点优先留给只有它能满足的宽度或深度需求。已运行或休眠的帧不被抢占。

### 7.4 递归、宽度与深度

尾递交和递归展开必须区分：

- **接受前能力不足**：尾递交；源节点释放。
- **节点已经接受帧且达到本地递归边界**：创建新的子任务；子任务重新从最弱节点开始，父节点进入 `SLP(CHILD)` 并保持占用。

单次展开产生的直接子分支超过本机槽位时：

- 若 epoch 中存在能够容纳的节点，轮询等待该节点空闲；
- 若当前冻结拓扑中没有任何节点满足，当前分支进入 `BLOCK(WIDTH)`；
- 如果分布式父子调用栈占满所有可能节点，且没有任何节点已抵达叶子或可释放等待点，则进入 `BLOCK(DEPTH)`。

`BLOCK(WIDTH/DEPTH)` 不能通过运行中热加计算机解除。玩家必须停止所有任务后重建 epoch。兄弟分支可以继续推进，父节点聚合状态，不因第一个警告取消整棵任务。

### 7.5 循环

每个帧保存祖先 `TaskKey` 路径；依赖再次出现于祖先路径时形成确定性循环。

- 没有傻子节点：帧进入 `SLP(LOOP)`，等待玩家补充替代样板或取消。
- 当前 epoch 有傻子节点，且所有可选加工路径均成环：傻子返回 `HALT(LOOP_ABORT)`。
- `LOOP_ABORT` 传到根并停止整个根任务，不能跳过循环分支继续制造无用中间产物。
- 连续订单每一批拥有新的迭代 ID，合法的批次重复不会被识别为任务环。
- 僵尸村民 `0/0` 不参与循环终止。

### 7.6 订单模式

- `FINITE`：生产并发送指定数量后完成。
- `CONTINUOUS`：重复生产和配送批次，直到玩家停止。

连续订单每完成一个批次必须释放当前计算机，再按最弱优先重新排队，不能长期占用高等级图书管理员节点。

## 8. Epoch、卸载与持久化

### 8.1 冻结拓扑

第一个任务启动时创建 `ClusterEpoch`，冻结计算机结构边界、协调节点、所有 `computerId` 及其硬件参数：

- 运行中新增的节点只显示为待加入，不参与当前 epoch。
- 被破坏的节点不由新节点替代。
- 区块卸载不是成员变更；相同 `computerId` 重载后仍属于 epoch。
- 宽度或深度阻塞期间不能热修改拓扑。
- 只有所有根任务停止、邮箱为空、节点空闲且所有 epoch 成员在线确认后才能关闭 epoch 并重新组网。

### 8.2 不强制加载区块

系统不申请 chunk ticket：

- 计算机卸载时，它持有的帧和队列冻结；其他节点上的独立分支继续。
- 样板核心或工厂代理卸载时，依赖它的帧休眠。
- 已发送的加工请求不会因为超时或重载自动重发。
- 仓储唤醒采用电平语义：重载后重新读取实际库存，因此丢失一次事件脉冲不会造成永久等待。

### 8.3 本地持久化

面板保存：

- `clusterId`；
- `LogisticsBinding` 列表；
- UI 偏好。

样板核心保存：

- 图书管理员完整实体快照；
- 已确认书库成员和结构状态；
- 页面指纹、增量解析/查询游标与缓存；
- 活动查询及回复。

计算机保存：

- `computerId` 与锁定硬件配置；
- 结构/协调摘要和 epoch；
- 控制队列、工作槽、活动 frame；
- 尚未 ACK 的 offer/reply；
- 已确认的 dispatch。

任务与消息使用稳定身份：

- `jobId`：一个根订单；
- `frameId`：一个任务帧；
- `epochId`：冻结拓扑；
- `messageId`：一次 offer/reply/dispatch 所有权转移。

接收端按 `messageId` 幂等处理；发送端只在收到所有权 ACK 后删除本地待发送记录。网络超时可以重新发送尚未 ACK 的协议消息，但不能重新执行已经确认的 Create 包裹 dispatch。

不保存按时间排列的调度日志：

- offer 在所有权 ACK 后删除；
- child reply 在父 ACK 后删除；
- 完成的子树只留下父节点的聚合计数；
- 根通知完成后删除根帧；
- 取消或 fault 清理本地帧、等待、offer 和 reply，但不召回已发包裹；
- 加载审计只清理可以证明的孤儿，离线 epoch 成员不视为消失。

所有改变只调用正常 dirty/同步机制，绝不在交互或 tick 中执行完整世界保存、强制区块保存、读取玩家文件验证或等待 IO worker。

## 9. 面板 UI

UI 使用 Create 自身的构建与视觉体系：

- `StockKeeperRequestScreen/Menu`
- `AbstractSimiContainerScreen`
- `AllGuiTextures`、`AllIcons`
- `IconButton`
- `ScrollInput`、`SelectionScrollInput`
- `NoShadowFontWrapper`
- `LerpedFloat`
- Create 的 tooltip、声音和配色

不复制 AE 源码、控件或纹理，也不引入 LDLib 等另一套 UI 框架。

面板有两个分页：

### 9.1 仓储与下单

- 物流网络选择器，包括“全部网络”只读汇总视图。
- 搜索同一所选网络中 Stock Ticker 管理的真实库存。
- 全部网络视图显示按网络拆分的数量，不能直接下单。
- 选择目标物品、数量、`FINITE/CONTINUOUS` 模式。
- 必须选择订单 `logisticsId` 并填写最终 `deliveryAddress`。
- 显示物理工厂代理与虚拟样板是否可用于该网络。

### 9.2 实时任务与集群

- 当前根任务列表和实时展开的任务树。
- 简化状态与原因、阻塞宽度/深度、循环和路由状态。
- 当前 epoch 的计算机节点、固定配置、占用与在线情况。
- 样板核心状态、通信距离、搜索预算、队列数和坏页面定位。
- 允许无视非致命警告继续，因为系统本身就是流式执行；只有 `BLOCK` 或 `HALT` 阻止对应分支。
- 提供停止单个根任务和“停止全部并准备重组”操作。

实时完成动画可以只存在客户端；服务器不为了 UI 保存历史调度日志。

## 10. 通信粒子

语义信号复用 Create `WiFiParticle.Data` 和既有无线物流视觉语言，不注册近似的新粒子，也不绘制跨距离连线。

产生粒子的事件：

- 面板发出订单；
- 计算机接受根任务；
- 计算机派发子任务或尾递交，源端发送、目标端接收；
- 计算机查询样板，计算机发送、样板核心接收；
- 样板核心返回匹配，核心发送、计算机接收；
- 加工任务正式下发；工厂仪表继续使用自身现有效果；
- 仓储实际变化唤醒计算机；
- 最终配送成功，执行节点发送、当前打开/关联面板接收。

抑制规则：

- ACK、keepalive、缓存命中、重试轮询和清理消息不显示。
- 同一端点同一 tick 的多次发送或接收合并成一次。
- 不为每条内部消息播放声音；只在玩家下单、绑定成功和拒绝时播放 Create 风格确认/拒绝音。
- 粒子在端点所属的本地 Level 与本地坐标生成，让 Sable 的空间渲染负责显示；不在根世界复制第二份粒子。
- 通过方块事件或既有 BE 同步通知正在追踪端点的客户端，不新增专用粒子网络包。

## 11. 故障与恢复

### 11.1 结构故障

- 计算机外壳开孔、总线断开或部分卸载：结构节点进入 `SLP(OFFLINE)`，任务不丢失。
- 恢复相同节点 UUID 和外壳后继续。
- 当前 epoch 协调节点被破坏时必须停止全部任务再重组。
- 样板书库断开、过大、双核心冲突或核心卸载：查询进入 `SLP(PATTERN)`。
- 已经取得不可变样板快照的帧不因后续书页修改失效。

### 11.2 样板与路由故障

- 单页错误只禁用该页并显示来源。
- 当前搜索找不到样板进入 `SLP(PATTERN)`，不是数据 fault。
- 代理卸载进入 `SLP(PROXY)`。
- 地址暂不可达或打包机繁忙进入 `SLP(ROUTE)`。
- 已确认派发的包裹不因超时重复发送。

### 11.3 任务完整性故障

- 普通缺料、缺样板、卸载或路由问题只休眠。
- `BLOCK(WIDTH/DEPTH)` 锁定当前 epoch，直到玩家停止任务。
- 只有损坏的 frame 数据、重复所有权、身份冲突或不可能的状态转换产生 `HALT(FAULT)`。
- 服务器对所有下单、取消、绑定和地址修改包重新校验菜单、玩家、空间、`clusterId`、`logisticsId` 与权限。

## 13. 验收矩阵

### 13.1 结构与实体

- 样板核心转换成功、上方受阻拒绝、非图书管理员拒绝、纸箱返还。
- 核心普通破坏和潜行扳手均恰好释放一个原图书管理员并还原/掉落讲台。
- 村民姓名、交易、职业等级、AI 和组件完整恢复。
- 普通村民、各等级图书管理员、傻子、流浪商人和僵尸村民锁定正确参数。
- 计算机破坏恰好释放一个半颗心原实体并掉落空计算机。
- `3×3×3` 到 `7×7×7`、非立方外壳、孔洞、非法内部块、隔离总线、33 节点分别验证。
- 64 成员/16 格边界通过；65 成员、17 格跨度和双核心冲突拒绝。

### 13.2 样板

- 六本书与笔提供 600 页容量。
- 搜索预算在 600 截止，多查询轮询公平。
- 普通书架增加派发队列，不改变页面预算。
- 坏 JSON、坏版本、非法数量、错误组件只禁用单页。
- 修改一页只失效一页缓存；重载后可从书页重建全部索引。
- 任务选中样板后修改原页，不改变已运行帧的不可变快照。

### 13.3 调度与物流

- 所有根/子任务均从最弱可用节点开始，能力不足尾递交后源节点释放。
- 验证直接宽度超过 slots 时的等待与 `BLOCK(WIDTH)`。
- 验证全调用栈无叶子时的 `BLOCK(DEPTH)`。
- 无傻子循环休眠；有傻子且无替代路径时根级 `LOOP_ABORT`。
- 连续订单完成一批后释放并重新排队。
- 多任务争抢同一真实库存时不复制、不负库存、不依赖 Promise。
- 工厂仪表和 JSON 样板能够作为相同候选代理参与选择。
- 加工地址与最终配送地址严格分离。
- 有限订单准确完成；连续订单可由玩家停止。

### 13.4 多物流网络

- 面板绑定多个 `logisticsId`，重复绑定去重，权限不足拒绝。
- 单网络库存准确；全部网络视图正确拆分与汇总。
- 全部网络视图不能直接下单。
- 每个订单、任务帧、工厂代理、库存读取和最终地址均保持所选 `logisticsId`。
- 不从其他已绑定网络误取料，也不把其他网络库存计为任务结果。
- 相同地址字符串存在于两个网络时不会混淆。

### 13.5 卸载、重启与 Sable

- 计算机、样板核心、工厂代理和面板分别卸载/重载。
- 服务器保存与重启后活动 frame、offer/reply、dispatch、epoch 和村民快照恢复。
- 世界—世界、世界—sublevel、sublevel—sublevel 通信。
- 样板距离严格使用外部坐标，64、流浪商人增益和 512 边界正确。
- 单个多方块跨空间组成被拒绝。
- Sable 整体移动双格核心、书库、计算机外壳和节点，不释放或复制实体。
- Sable 只移动结构一部分时暂停，不删除任务或村民；恢复后继续。
- 无 Sable 环境启动和运行正常。

### 13.6 UI、粒子与服务器安全

- 两个分页使用 Create 组件和风格，窗口缩放与滚动正常。
- 实时任务树不要求服务器保存历史日志。
- 所有规定的语义事件产生 Create WiFi 粒子；ACK/轮询不产生。
- 同端点同 tick 合并粒子。
- sublevel 中粒子只在正确本地空间渲染，不在根世界重复。
- 伪造 `clusterId`、未绑定 `logisticsId`、错误空间身份、无权限、过期菜单和非法地址均由服务端拒绝。
- 客户端、集成服务器与独立服务端均通过编译和运行检查。
