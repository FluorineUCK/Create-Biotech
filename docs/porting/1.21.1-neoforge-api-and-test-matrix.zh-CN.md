# Create: Biotech 1.21.1 NeoForge API 变化与回归测试矩阵

## 1. 文档目的

本文档回答三个问题：

1. 从 Minecraft 1.20.1 Forge/Create 6 到 Minecraft 1.21.1 NeoForge/Create 6，本项目实际遇到了哪些 API 变化。
2. 哪些方块、物品和系统最容易出现“能启动但功能已坏”的移植问题。
3. 应在什么条件下测试，看到什么结果才算通过。

本文档依据 `1.20.1..1.21.1` 的实际代码差异编写，不是通用升级指南。

## 3. 本项目实际遇到的 API 变化

### 3.1 构建与模组入口

| 1.20.1 | 1.21.1 | 对本项目的影响 |
| --- | --- | --- |
| Forge/LegacyForge 工具链 | NeoForge ModDevGradle | 构建插件、依赖坐标、运行配置和元数据全部迁移 |
| `mods.toml` | `neoforge.mods.toml` | 依赖范围和加载器约束重新声明 |
| Java 17 | Java 21 | Mixin compatibility level、Gradle toolchain 和运行实例统一升级 |
| `FMLJavaModLoadingContext.get()` | 构造器注入 `IEventBus`、`ModContainer` | 模组主类不再主动获取加载上下文 |
| `MinecraftForge.EVENT_BUS` | `NeoForge.EVENT_BUS` | 服务器 Tick、实体与运行期事件监听改挂 NeoForge 总线 |

项目证据：`build.gradle`、`gradle.properties`、`CreateBiotech.java`。

### 3.2 注册表

| 1.20.1 | 1.21.1 |
| --- | --- |
| `ForgeRegistries` | `BuiltInRegistries`、`Registries`、`NeoForgeRegistries.Keys` |
| `RegistryObject<T>` | `DeferredHolder<R, T>` |
| Forge `DeferredRegister` | NeoForge `DeferredRegister` |
| `new ResourceLocation(namespace, path)` | `ResourceLocation.fromNamespaceAndPath(...)` 或 `parse(...)` |

影响范围包括方块、方块实体、物品、实体、菜单、流体、粒子、配方类型、
配方序列化器、数据组件和自定义原料类型。注册 ID 必须与 1.20.1 保持一致。

项目证据：`CBBlocks.java`、`CBBlockEntityTypes.java`、`CBItems.java`、
`CBRecipeTypes.java`、`CBIngredients.java`。

### 3.3 Capability

1.20.1 主要由方块实体覆盖 `getCapability` 并返回 `LazyOptional`；1.21.1 改为：

- 在 `RegisterCapabilitiesEvent` 中按方块实体类型注册。
- 使用 `Capabilities.ItemHandler.BLOCK` 和 `Capabilities.FluidHandler.BLOCK`。
- 查询结果直接按方块、位置和方向解析，不再依赖 Forge `LazyOptional` 生命周期。

本项目有 18 个 capability 注册点，覆盖：

- 物品：生物打包机、潜影打包机、唤魔者附魔室、固定胡萝卜钓竿、爆破室、
  防爆保险库、蜘蛛装配台、培养皿、史莱姆/岩浆传送带、悦灵驿站。
- 流体：唤魔者附魔室、经验母岩、经验泵、下界传送门流体、蜘蛛装配台、
  培养皿、鱿鱼打印机。

项目证据：`CBCapabilities.java`。

### 3.4 网络

| 1.20.1 | 1.21.1 |
| --- | --- |
| Forge `SimpleChannel` | `CustomPacketPayload`/Catnip packet registry |
| 自增消息 ID + `NetworkDirection` | 明确的客户端/服务端 payload 类型 |
| `FriendlyByteBuf` | `RegistryFriendlyByteBuf` |
| `NetworkEvent.Context` | 处理器直接取得 `ServerPlayer` 或 `LocalPlayer` |
| Forge `PacketDistributor` | Catnip 的 player、tracking entity、tracking chunk 分发 |

当前协议版本为 `14`，有 8 个 C2S 逻辑包和 6 个 S2C 逻辑包。重点风险是：

- 方向注册错误。
- 客户端类在专用服务器上被提前类加载。
- 编码顺序与解码顺序不一致。
- tracking entity/chunk 的接收者范围错误。
- 菜单关闭或实体移除后收到延迟包。

项目证据：`CBPackets.java`。参考：
`ref/1.21.1/Create/src/main/java/com/simibubi/create/AllPackets.java`。

### 3.5 物品 NBT 与数据组件

1.21.1 的物品状态以数据组件为主：

- 通用旧 NBT 通过 `DataComponents.CUSTOM_DATA`/`CustomData` 兼容读取。
- 悦灵快递员的货物和朝向改为持久化、网络同步的自定义 `DataComponentType`。
- Create 包裹内容、药水内容、附魔等改从对应数据组件读取。
- `ItemStack` 的复制、合并、序列化和网络同步都必须保留组件。

高风险对象：

- 装有生物的大小纸箱。
- 潜影包裹和 Create 包裹。
- 悦灵快递员。
- 附魔书复制结果。
- 无线终端绑定信息。

项目证据：`CBItemData.java`、`CBDataComponents.java`、
`CapturedEntityBoxHelper.java`、`AllayCourierItem.java`。
Create 参考：`ref/1.21.1/Create/src/main/java/com/simibubi/create/AllDataComponents.java`。

### 3.6 SavedData 与注册表上下文

`SavedData` 的读写现在接收 `HolderLookup.Provider`，并通过
`SavedData.Factory` 注册。涉及：

- 潜影传送站地址表。
- 悦灵运输任务队列。

物品堆、实体或带注册表对象的数据在存档读写时也需要传入注册表上下文。
因此“放置后能用”不足以证明正确，必须重启服务器后再次验证。

项目证据：`ShulkerTeleporterSavedData.java`、
`AllayCourierTaskSavedData.java`。

### 3.7 配方、Codec 与自定义原料

主要变化：

- 手写 Gson/FriendlyByteBuf 序列化改为 `MapCodec` 和 `StreamCodec`。
- Create `ProcessingRecipe` 现在通过 `ProcessingRecipeParams` codec 工作。
- 标准加工配方使用 `StandardProcessingRecipe`。
- 流体原料使用 NeoForge `SizedFluidIngredient`。
- 自定义纸箱原料从 Forge `AbstractIngredient`/`IIngredientSerializer`
  改为 `ICustomIngredient`、`IngredientType` 和 `MapCodec`。
- 配方 JSON 中 `processing_time`、`heat_requirement`、`transitional_item`
  等字段改为 snake_case。
- 复合原料使用 `neoforge:compound`；带组件的流体原料使用
  `neoforge:components`。

高压聚爆配方还新增了 codec 化的 `exclusiveResults` 和
`result_count_ranges`，必须验证概率、互斥结果和数量范围。

项目证据：`CreeperBlastChamberHighPressureRecipe.java`、
`SquidPrinterRecipe.java`、`CapturedEntityBoxIngredient.java`。
Create 参考：

- `ref/1.21.1/Create/src/main/java/com/simibubi/create/content/processing/recipe/ProcessingRecipe.java`
- `ref/1.21.1/Create/src/main/java/com/simibubi/create/content/processing/recipe/StandardProcessingRecipe.java`

### 3.8 Minecraft 交互、菜单和客户端事件

实际遇到的变化包括：

- 部分方块交互由 `InteractionResult` 改为 `ItemInteractionResult`。
- `use`/`useOn`/`useItemOn` 的目标方法和参数发生变化。
- 菜单附加数据使用 `RegistryFriendlyByteBuf`。
- 菜单屏幕从客户端 setup 中直接注册改为 `RegisterMenuScreensEvent`。
- GUI overlay 改为 `RegisterGuiLayersEvent` 和 `VanillaGuiLayers`。
- 附加模型注册要求 `ModelResourceLocation`。
- 实体渲染层通过 `EntityRenderersEvent.AddLayers` 取得 renderer。

直接风险是右击无反应、客户端菜单数据错位、专用服务器类加载崩溃、
附加模型缺失和 overlay 不显示。

项目证据：`CreateBiotechClient.java`、`CBMenuTypes.java`。

### 3.9 Create 6 API

本项目实际受影响的部分：

- 加工配方 codec 与随机结果 API。
- PackageItem 内容改由 Create 数据组件保存。
- Funnel/Belt 的目标方法、方向解析和渲染路径变化。
- `BlockEntityConfigurationPacket` 的处理接口变化。
- Pressing、Basin、Fluid Tank、Stock Keeper 等目标方法描述符变化。
- Create 6 已原生支持复合原料，旧 `SequencedRecipeMixin` 已删除。
- Catnip 网络和平台服务替代 Forge 网络分发。

重点参考：

- `ref/1.21.1/Create/src/main/java/com/simibubi/create/content/logistics/box/PackageItem.java`
- `ref/1.21.1/Create/src/main/java/com/simibubi/create/content/logistics/funnel/BeltFunnelBlock.java`
- `ref/1.21.1/Create/src/main/java/com/simibubi/create/foundation/networking/BlockEntityConfigurationPacket.java`
- `ref/1.21.1/Create/src/main/java/com/simibubi/create/content/fluids/tank/FluidTankBlockEntity.java`

### 3.10 Ponder、Flywheel、JEI 与模型加载器

- Ponder API 位于独立的 `net.createmod.ponder` 包，并通过 `PonderPlugin`
  与新版注册 helper 注册场景和标签。
- Flywheel visual 使用 1.21.1 的 visualization/model API。
- JEI Forge 类型改为 `NeoForgeTypes`，配方查询返回 `RecipeHolder`，
  category、slot 与 GuiGraphics 相关签名有变化。
- 模型 loader 从 `forge:*` 改为 `neoforge:*`。
- 模型扩展字段从 `forge_data` 改为 `neoforge_data`。

参考：

- `ref/1.21.1/Ponder/common/src/main/java/net/createmod/ponder/api/registration/PonderPlugin.java`
- `ref/1.21.1/JustEnoughItems/CommonApi/src/main/java/mezz/jei/api/recipe/category/IRecipeCategory.java`
- `ref/1.21.1/JustEnoughItems/Library/src/main/java/mezz/jei/library/gui/recipes/RecipeLayout.java`

### 3.11 Mixin 目标与映射

Minecraft/Create 方法变化会让旧 Mixin 在“源码能编译”的同时于生产环境注入失败。
本次实际调整包括：

- `BasinBlock.use` 改为 `useItemOn`，返回值改为 `ItemInteractionResult`。
- `PortalForcer.findPortalAround` 改为 `findClosestPortalPosition`，返回
  `Optional<BlockPos>`。
- `SmartBlockEntity.read` 增加 `HolderLookup.Provider` 和客户端包标志参数。
- `LogisticalStockResponsePacket.handleClient` 改为 `handle`。
- Create 6 已原生处理复合原料，删除旧 `SequencedRecipeMixin`。

当第三方方法描述符含 `net.minecraft.*` 或 Mojang 渲染类型时，也不能为了让注入通过而
盲目设置 `remap = false`；必须让工具链处理描述符映射。运行验证应覆盖真正会触发这些
切点的工作盆、传送门、库存响应、漏斗、辊压机、流体储罐和渲染场景。

项目证据：`create_biotech.mixins.json` 及 `mixin/`、`mixin/client/`。

### 3.12 数据包目录与 JSON

Minecraft 1.21.1 使用单数数据目录：

| 旧目录 | 新目录 |
| --- | --- |
| `advancements/` | `advancement/` |
| `recipes/` | `recipe/` |
| `loot_tables/` | `loot_table/` |
| `tags/items/` | `tags/item/` |
| `tags/blocks/` | `tags/block/` |
| `tags/fluids/` | `tags/fluid/` |

此外进度图标物品堆使用 `id`，配方输出使用新版物品堆/流体堆结构，
Forge 公共标签迁移到 `c:`。

## 4. 测试优先级

- **P0：必须先测。** 同时跨越多个变化面，失败会破坏核心玩法、存档或网络。
- **P1：发布前必须测。** 单系统复杂功能、跨维度或客户端表现。
- **P2：完整性检查。** 静态方块、资源、兼容 UI 和数据包覆盖。

## 5. P0 核心回归矩阵

### 5.1 三种传送带、漏斗与动力连接

对象：史莱姆传送带、岩浆传送带、动力传送带、万向节、史莱姆离合器、
骨制棘轮、Create 漏斗/隧道/喷嘴。

- [ ] 沿 X/Z 方向分别连接、延长、拆除并重新连接三种传送带。
- [ ] 正转、反转、零转速、超高转速下检查物品移动方向与速度。
- [ ] 物品实体、生物和捕获小史莱姆分别经过传送带。
- [ ] 漏斗位于上、下、侧面时分别插入和抽取；推入与拉出形态都要测。
- [ ] 对漏斗使用扳手，确认形态切换、方向和碰撞箱正确。
- [ ] 岩浆传送带经过加工设备，验证加工交互只触发一次且输出不丢失。
- [ ] 动力传送带由玩家移动驱动时，测试站立、行走、疾跑、潜行和反向移动。
- [ ] 万向节在水平转垂直、垂直转水平、反向旋转时传递方向正确。
- [ ] 传送带跨区块边界，卸载/重载一侧后继续运输。
- [ ] 开启与关闭 Flywheel/实例化渲染后，漏斗 flap、传送带表面和万向节模型均正常。

通过标准：无复制/吞物、无方向翻转、无持续空转网络包、无 Mixin 注入错误。

### 5.2 爆破室核心与高压聚爆

- [ ] 分别搭建最小 `3×3` 和最大配置尺寸结构。
- [ ] 顶面中心朝下动力辊压机、底面中心生物打包机的方向必须被正确识别。
- [ ] 缺机壳、错误尺寸、辊压机朝向错误、底部机器缺失时不成型。
- [ ] 输入普通物品、空纸箱、非苦力怕纸箱时拒绝且不吞物。
- [ ] 普通苦力怕和闪电苦力怕大型纸箱分别加工。
- [ ] 检查 `exclusiveResults`：互斥配方一次只能选择一个结果。
- [ ] 检查 `result_count_ranges`：最小值、最大值和多次随机结果都在范围内。
- [ ] 输出保险库为空、半满、已满时检查暂停与恢复。
- [ ] 无动力、应力不足、辊压机堵塞时状态文本正确且不推进进度。
- [ ] 结构跨区块，主动卸载一部分区块时显示暂停，重新加载后恢复。
- [ ] 超过过载 RPM：分别测试爆炸开关开启/关闭、普通/闪电苦力怕倍率。
- [ ] 工作中保存退出并重启，进度、过载值、输入和结构角色不丢失。
- [ ] 护目镜信息、状态面板、苦力怕头像开关与爆炸粒子正确。

通过标准：输入输出守恒，结构状态可恢复，概率结果合法，爆炸只在配置允许时发生。

### 5.3 纸箱、生物打包机与潜影打包机

- [ ] 小纸箱捕获白名单内小型生物，并潜行右击释放。
- [ ] 小纸箱对不允许的生物、玩家、Boss 和已移除实体拒绝。
- [ ] 大纸箱致命捕获在生存/创造以及配置开关的组合下符合预期。
- [ ] 装有生物的纸箱掉落、拾取、移容器、过漏斗、重登后仍保留实体类型和数据。
- [ ] 装箱物品不可错误堆叠；复制、拆分或创造模式中键不会丢组件。
- [ ] JEI 中自定义“捕获实体纸箱”原料显示正确，并只匹配指定实体。
- [ ] 装箱小史莱姆通过漏斗进入工作盆，材料化为捕获小史莱姆物品。
- [ ] 装箱纸箱经过机械锯时按设计释放/加工，且不会重复生成实体。
- [ ] 生物打包机静态使用和装在动态结构上使用，客户端动画与服务端库存一致。
- [ ] 潜影打包机绑定另一台打包机，测试正常目标、目标已满、目标被拆除、目标区块卸载。
- [ ] Create 包裹、潜影包裹和虚拟 fallback 内容均能被正确读取。
- [ ] 保存退出后重新读取装箱物品与两类打包机库存。

通过标准：实体与物品不会复制或消失；组件、包裹内容和动画同步一致。

### 5.4 蜘蛛装配台

- [ ] 打开菜单，所有槽位、流体槽和锁定按钮位置正确。
- [ ] 单槽锁定/解锁和“一键锁定全部”在重开菜单、重登后保持。
- [ ] 从每个方向测试物品 capability 插入/抽取。
- [ ] 从每个方向测试流体 capability 注入/抽取和容量上限。
- [ ] 只给部分材料、错误材料、错误流体时不启动。
- [ ] 完整配方分别走机械手臂/部署器步骤和机械锯步骤。
- [ ] 零转速、反转、低速、高速时动画、耗时和输出正确。
- [ ] 输出槽已满时停机，腾出空间后只生成一次结果。
- [ ] 工作中保存退出并重启，库存、流体、锁定状态和加工进度合理恢复。
- [ ] 普通 renderer 与 Flywheel visual 下身体、头、腹部和腿动画一致。

### 5.5 经验流体链

对象：传送液、下界传送门流体方块实体、经验泵、经验母岩、经验芽/簇、
Create 流体储罐。

- [ ] 用 Create 动力泵从下界传送门抽取传送液。
- [ ] 管道从不同方向连接，检查流体 capability 方向和模拟抽取。
- [ ] 经验泵吸收经验球并输出经验流体，数量守恒。
- [ ] 经验流体进入普通 Create 储罐，液面/经验球特殊渲染无崩溃。
- [ ] 关闭或不使用特殊渲染路径时，普通流体 fallback 仍可显示。
- [ ] 经验母岩自然随机生长和主动输入经验加速生长。
- [ ] 四个生长阶段的采集物、掉落和直接使用吸收经验值正确。
- [ ] 流体容器已满、管道堵塞、经验球极多时无复制、负数或卡死。
- [ ] 载入 1.20.1 含经验泵/经验流体的存档副本，检查 legacy refresh。

## 9. 推荐执行顺序

1. **专用服务器类加载烟测**：不带 JEI/Jade 等客户端模组启动并进入可接受连接状态。
2. **注册与资源烟测**：创造标签页、JEI、Ponder、模型、配方、进度和战利品表。
3. **传送带与 capability**：先验证所有通用物流接口。
4. **纸箱与数据组件**：验证物品状态可跨容器、网络和重启保存。
5. **爆破室、蜘蛛装配台、经验链**：验证复杂加工与 codec。
6. **悦灵物流与潜影传送站**：验证 payload、SavedData、跨维度和区块卸载。
7. **动态结构与渲染**：热气球、缓冲垫、Flywheel 和客户端效果。
8. **1.20.1 存档升级**：只对存档副本测试，不覆盖原存档。
9. **两客户端并发**：菜单、配置、派单和跟踪实体同步。
10. **最终日志审计**：检查 ERROR/FATAL、Mixin、codec、payload 和 SavedData 异常。

## 10. 每项测试的统一通过标准

每一个复选项只有同时满足以下条件才可勾选：

- 服务器状态是权威结果，客户端没有只显示但未实际生效的假象。
- 输入、流体、实体和输出守恒，不复制、不吞失、不出现负数。
- 保存退出并重启后状态仍然合理。
- 区块卸载、目标失效或输出堵塞时安全暂停，不销毁数据。
- 两客户端看到的方块状态、动画、菜单和实体一致。
- 日志无本模组引发的 ERROR/FATAL、Mixin 注入失败、payload 解码失败或 codec 错误。
- 测试后没有幽灵地址、幽灵运输任务、重复实体或永久加载区块。
